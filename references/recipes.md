# 高频套路

## 1. 冷启动到目标页

```
launch <pkg>            # 失败会报前台是谁
waittext <首页特征词> --timeout 25
see                     # 拿控件编号
```

首次启动常弹「隐私政策/青少年模式/更新」：`find 同意` 或 `find 跳过` → `tapnode`，然后重新 `see`。

## 2. 搜索三件套

```
find 搜索              # 找搜索框或搜索按钮，记下编号
tapnode <idx>          # 点进搜索页/聚焦输入框
text "关键词"           # 中文自动走 ADBKeyboard
key enter              # 有的 App 要用右侧「搜索」按钮，先看 see 的控件
waittext <预期结果词> --timeout 20
see                    # 读结果并汇报
```

## 3. 列表滚到底

一次只滚一屏、滚完必看，别连滚 10 次：

```
see                    # 记下当前最后一个可见条目文本
scroll down
see                    # 对比：出现新条目 → 继续；条目完全没变 → 到底了
```

同一位置连续两次没有新内容就是到底（或加载中），可以 `waittext` 再判一次。

## 4. 表单填写

```
tapnode <输入框编号>
text "内容"
tapnode <下一个输入框编号>   # 点下一个反而会自动收起键盘、更稳
...
see                          # 提交前逐项复核：金额、地址、日期、手机号
```

`key back` 关键盘会把页面也退一层，优先用「点下一个框」的方式收键盘。

## 5. 弹窗清场

`see` 里出现按钮对：「允许/拒绝」「同意/不同意」「立即更新/以后再说」「开通/取消」：

- 与目标直接相关（定位、通知用于任务）→ 允许；
- 纯打扰（更新、推荐、会员、广告）→ 以后再说 / 关闭 / 取消；
- **绝不点**「立即开通」「免费试用」「领取」「一键安装」。

## 6. 微信/QQ 里发消息、转发、打开小程序

- 发消息前必须向用户确认收件人和内容，发完把聊天页留在屏幕上汇报。
- 转发到「文件传输助手」给自己是最安全的自测路径。
- 小程序加载慢，`waittext` 超时给 25 秒以上，别反复点。

## 7. 读屏幕而不是操作

用户只想知道屏幕上有什么（余额、验证码、物流、聊天、通知）：

```
see                     # 控件文本就是答案，直接读
```

读不到（图片/验证码）就 Read `SHOT` 用视觉读，并把关键内容简短转述，别整屏复述。

## 8. 卡住时的固定排查顺序

1. 重新 `see`（界面可能已变）；
2. `key back` 退一层再来；
3. 换关键词 `find`；
4. `scroll` 找目标；
5. 冷启动 `launch` 重进；
6. 还不行：`waittext` 判断是不是加载/网络问题，然后如实回报用户，别硬凑。
